Soru 1:
ConcurrentHashMap İçinde Thread Safety'i Nasıl Sağlar?

ConcurrentHashMap, tüm haritayı kilitlemek yerine bucket-level synchronization (segmentasyon) kullanır.

Temel İlkeler:

1. Bucket Bölümleme: Harita 16 (veya daha fazla) segment'e bölünür. Her segment bağımsız olarak kilitlenir.

// ConcurrentHashMap sadece ihtiyaç duyduğu segment'i kilitler // Thread 1: Bucket 0'ı kilitler // Thread 2: Bucket 5'i kilitler (aynı anda yapabilir!)

2. CAS (Compare-and-Swap) Operasyonları: Java 8+ versiyonlarda atomik işlemler için kullanılır.

3. Null Değer Kısıtlaması: HashMap'ten farklı olarak ne key ne de value null olamaz.

Uygulamada Kullanımı:

ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>(); // Thread-safe operasyonlar map.putIfAbsent("count", 0); // Atomik map.computeIfPresent("count", (k, v) -> v + 1); // Atomik // HashMap ile bunu yaparsanız race condition oluşur!
HashMap'i multi-threaded ortamda senkronize etmek için Collections.synchronizedMap() kullanabilirsiniz, fakat ConcurrentHashMap daha performanslıdır.
ConcurrentHashMap'te iteration sırasında kilitlenme olmadığından, döngü sırasında eklenen yeni elemanlar görülmeyebilir (bu istenen davranıştır).
Soru 2:
wait(), sleep() ve join() Arasındaki Farklar Nelerdir?
Metod Monitor Lock'u Serbest Bırakır Kullanım Amacı Uyandırılma Koşulu
wait() ✓ Evet Thread'i başka thread'in notification'ını beklemesi için uyutma notify() veya notifyAll() çağrılmasında
sleep() ✗ Hayır Thread'i belirli bir süre için uyutma Zaman dolduğunda otomatik
join() ✗ Hayır Bir thread'in diğer thread'in bitmesini beklemesi Hedef thread sonlandığında

Detaylı Örnekler:

wait() - Prodüktör/Tüketici Deseni:

synchronized void consume() { while (buffer.isEmpty()) { wait(); // Lock'u serbest bırakır, diğer thread'ler çalışabilir } buffer.remove(); } synchronized void produce() { buffer.add(item); notifyAll(); // Bekleyen thread'leri uyandır }

sleep() - Basit Gecikmeler:

for (int i = 0; i < 5; i++) { System.out.println("Countdown: " + (5 - i)); Thread.sleep(1000); // Lock'u tutmaya devam eder }

join() - Thread Sıralaması:

Thread thread1 = new Thread(() -> { System.out.println("Thread 1 çalışıyor"); }); thread1.start(); thread1.join(); // Main thread'i Thread 1'in bitmesini bekle System.out.println("Thread 1 bitti, artık main devam edebilir");

Hafızda Kalması Gereken Noktalar:

  • wait() ve notify() mutlaka synchronized blok içinde olmalı
  • sleep() thread'i kesmez, interrupt edilebilir
  • join() timeout ile kullanılabilir: thread.join(5000)
Soru 3:
Java Class Loading Mekanizmasını Açıklayınız

Class loading, bir .class dosyasını JVM'ye yükleme ve kullanıma hazır hale getirme işlemidir. Üç aşamadan oluşur:

1. Loading (Yükleme) - Üç Class Loader Türü:

Class Loader Hiyerarşisi:

  • Bootstrap ClassLoader: Java standart kütüphaneleri (java.lang, java.util vs) yükler. JVM'nin parçasıdır.
  • Platform ClassLoader: (Java 9+) Extension ClassLoader yerine kullanılır. JDK'nın platform modülleri yükler.
  • Application ClassLoader: Uygulamanızın class'larını yükler. CLASSPATH'den bulur.

Parent Delegation: Çocuk ClassLoader'ı, kendi yüklü bulunmayan bir class için önce parent'ına sorar.

// Hangi ClassLoader bir class'ı yükledi? ClassLoader loader = String.class.getClassLoader(); System.out.println(loader); // null (Bootstrap ClassLoader gösterilmez) ClassLoader loader2 = MyClass.class.getClassLoader(); System.out.println(loader2); // sun.misc.Launcher$AppClassLoader

2. Linking (Bağlantı):

Verification: .class dosyasının formatı kontrol edilir

Preparation: Static değişkenler için bellek ayrılır

Resolution: Symbolic referanslar gerçek memory adreslerine dönüştürülür

3. Initialization (Başlatma):

Static bloklar ve static değişkenler ilk değerlendirilir.

public class MyClass { static { System.out.println("Initialization çalıştı!"); // Class ilk kez yüklenince çalışır } static int count = 10; }
Custom ClassLoader'ları plugin sistemleri ve dinamik sınıf yüklemesi için kullanabilirsiniz.
Soru 4:
equals() ve == Arasındaki Fark Nedir?
Operatör Kıyaslama Türü Kullanım
== Referans karşılaştırması Primitive'ler ve object referansı
equals() Mantıksal eşitlik Obje içeriğinin karşılaştırılması

Pratik Örnek:

String s1 = new String("Java"); String s2 = new String("Java"); System.out.println(s1 == s2); // false (farklı obje referansları) System.out.println(s1.equals(s2)); // true (aynı içerik) // Primitive'ler için: int a = 10; int b = 10; System.out.println(a == b); // true (değerler aynı)

equals() Kendi Sınıfımızda Implement Etme:

public class User { String email; int age; @Override public boolean equals(Object obj) { if (this == obj) return true; if (obj == null) return false; if (!(obj instanceof User)) return false; User other = (User) obj; return this.email.equals(other.email) && this.age == other.age; } @Override public int hashCode() { // hashCode'u da override etmemiz GEREKLI! return Objects.hash(email, age); } }
equals() override ettiğinizde mutlaka hashCode() da override edin! Aksi takdirde HashMap/HashSet'te sorun yaşarsınız.

hashCode() - equals() Kuralı:

  • Eğer equals() true dönerse, hashCode() aynı değeri döndürmelidir
  • Eğer equals() false dönerse, hashCode() farklı değer döndürebilir (ama aynı da dönebilir)
Soru 5:
JVM'de Garbage Collection Nasıl Çalışır?

Temel Kavram:

Garbage Collection, artık kullanılmayan nesneleri otomatik olarak belleğinden silen JVM özelliğidir. Reachability (ulaşılabilirlik) üzerine kuruludur.

Heap Yapısı - Generational GC:

Nesiller (Generations):

  • Young Generation: Yeni yaratılan nesnelerin bulunduğu alan. Hızlı ölür.
  • Old Generation: Young generation'dan "yaşa çıkan" nesneler buraya taşınır.
  • Permanent Generation / Metaspace: Class metadata ve String pool

GC İşlem Adımları:

1. Mark Phase: Hangi nesnelerin ulaşılabilir olduğunu işaretler 2. Sweep Phase: İşaretlenmeyen nesneleri siler 3. Compact Phase: Belleği organize eder (bazı collector'larda)

GC Türleri:

Minor GC: Young generation'ı temizler (hızlı, sık)

Major GC: Old generation'ı temizler (yavaş, nadir)

Full GC: Tüm heap'ı temizler (çok yavaş, ender)

Modern Collector: G1 GC

G1 GC heap'ı bölgelere (region) ayırır ve region-by-region işlem yapar, daha düşük pause time sağlar.

// GC log'larını görmek için (production'da kullanmayın): // java -Xlog:gc -Xmx1G MyApp // GC pause'ları azaltmak için: // java -XX:+UseG1GC -XX:MaxGCPauseMillis=200 MyApp
Memory leak: Hala referanslı olan ama artık kullanılmayan nesneler GC'den kurtulmazlar. Statik koleksiyonlara sınırsız ekleme yaparsanız memory leak oluşur.
Soru 6:
volatile ve synchronized Arasındaki Fark Nedir?
Özellik volatile synchronized
Amaç Visibility (görünürlük) garantisi Mutual exclusion (karşılıklı dışlama)
Lock kullanır mı? Hayır Evet
Atomiklik Sadece read/write için Block içindeki tüm operasyonlar
Performans Daha hızlı Daha yavaş ama güvenli

volatile Nedir?

Volatile bir değişkenin her okuma/yazması ana belleğe gider, CPU cache'ine değil. Böylece diğer thread'ler en güncel değeri görür.

private volatile boolean flag = false; // Visibility garantili // Thread 1 flag = true; // Thread 2 (hemen görür) while (!flag) { // bekleme }

volatile'in Sınırlaması:

private volatile int count = 0; // BU PROBLEM: count++ atomik değildir! // 1. Mevcut değeri oku (10) // 2. Bir ekle (11) // 3. Yaz (11) // İkinci thread araya girerse: her iki thread'in increment'i kaybolabilir // Çözüm: private volatile int count = 0; synchronized void increment() { count++; // Artık atomik }

synchronized Ne Yapar?

public synchronized void transfer(Account from, Account to, int amount) { if (from.balance >= amount) { from.balance -= amount; // Critical section başlangıcı to.balance += amount; // Critical section sonu // Başka thread'ler bu süre boyunca bu metodu çağıramaz } }
Baskı düşük ise volatile, baskı yüksek ise AtomicInteger veya ReadWriteLock kullanın.
Soru 7:
Shallow Copy vs Deep Copy - Fark Nedir?

Shallow Copy (Yüzeysel Kopya):

Sadece referansları kopyalanır, nested obje'ler paylaşılır.

public class Person { String name; Address address; // Nested obje } Person original = new Person(); original.name = "Ali"; original.address = new Address(); original.address.city = "İstanbul"; // Shallow copy Person copy = original; // YANLIŞ: Aynı obje referansı copy.address.city = "Ankara"; System.out.println(original.address.city); // "Ankara" - Original da değişti!

Deep Copy (Derin Kopya):

Nested obje'ler de kopyalanır, tamamen bağımsız nesneler oluşur.

public class Person implements Cloneable { String name; Address address; @Override public Person clone() throws CloneNotSupportedException { Person copy = (Person) super.clone(); // Nested objeyi de kopyala copy.address = new Address(); copy.address.city = address.city; return copy; } } Person original = new Person(); Person deepCopy = original.clone(); deepCopy.address.city = "Ankara"; System.out.println(original.address.city); // "İstanbul" - Original değişmedi

Ne Zaman Kullanmalı?

  • Shallow Copy: Immutable nested obje'ler varsa (String, Integer)
  • Deep Copy: Mutable nested obje'ler varsa (List, Map, custom obje'ler)
En kolay yol: Jackson kütüphanesini kullanarak JSON'a çevir, geri dönüştür (deep copy garantili).
Soru 8:
Checked vs Unchecked Exceptions - Fark Nedir?
Tür Parent Class Compile-Time Check Örnek
Checked Exception Exception ✓ Evet (zorunlu handle etme) IOException, SQLException
Unchecked Exception RuntimeException ✗ Hayır (opsiyonel) NullPointerException, ArrayIndexOutOfBoundsException

Checked Exception Örneği:

public void readFile(String filename) throws IOException { // IOException checked exception'dır // Ya try-catch ya da throws kullanmalısınız FileReader file = new FileReader(filename); } // Çağrıldığında try { readFile("data.txt"); } catch (IOException e) { e.printStackTrace(); }

Unchecked Exception Örneği:

public void divide(int a, int b) { // ArithmeticException unchecked // Compile error yoktur, ama runtime'da çıkabilir return a / b; // b == 0 ise çöker }

Uygulamada Seçim:

// Checked Exception: Beklenen dış hatalar public User getUserFromDatabase(int id) throws SQLException { // Veritabanı bağlantısı başarısız olabilir } // Unchecked Exception: Programcı hatası (invalid parameter) public void setAge(int age) { if (age < 0) { throw new IllegalArgumentException("Yaş negatif olamaz"); } this.age = age; }
Modern API'ler daha çok unchecked exception'lar tercih eder (try-catch'ten kurtulmak için). Checked exception'lar sadece gerçekten recover edilebilir durumlarda kullanın.

ThreadLocal Nedir ve Pratik Kullanım Örneği?

ThreadLocal Nedir?

Her thread'in kendi değişken kopysını tutmasını sağlayan bir veri yapısıdır. Bir thread başka thread'in değerini göremez.

// Sabit bir ThreadLocal tanımı private static final ThreadLocal<String> userContext = ThreadLocal.withInitial(() -> "guest"); // Thread 1 userContext.set("Ali"); System.out.println(userContext.get()); // "Ali" // Thread 2 (aynı anda) userContext.set("Fatma"); System.out.println(userContext.get()); // "Fatma" // Thread 1'de tekrar sorgulasak: // System.out.println(userContext.get()); // "Ali" - değişmedi!

Pratik Örnek: Web Request Context

public class RequestContext { private static final ThreadLocal<String> requestId = new ThreadLocal<>(); private static final ThreadLocal<String> userId = new ThreadLocal<>(); public static void setRequestId(String id) { requestId.set(id); } public static String getRequestId() { return requestId.get(); } // Her request'te temizlemek zorunlu! public static void cleanup() { requestId.remove(); userId.remove(); } } // Spring Controller'da @PostMapping("/api/users") public User createUser(@RequestBody User user) { String correlationId = UUID.randomUUID().toString(); RequestContext.setRequestId(correlationId); try { // Log, service çağrıları vs. request ID'yi kullanabilir logger.info("Request ID: " + RequestContext.getRequestId()); return userService.create(user); } finally { RequestContext.cleanup(); // UNUTMAYIN! } }
ThreadLocal Memory Leak'ler ThreadPool'larda (Tomcat, ThreadPoolExecutor) yaşanır çünkü thread'ler yeniden kullanılır. Cleanup() yapmazsanız önceki request'in verileri yeni request'te görülebilir!
Reactive/Async kodda ThreadLocal yerine Context API veya Spring Security'nin SecurityContext'i (ContextHolder) kullanın.
Soru 10:
Yüksek Volume Ödeme Sisteminde Thread-Safe Hesap Bakiyesi Güncellemesi

Problem:

İki thread aynı anda son 100 TL'yi çekmeye çalışıyor. İkisinin de başarılı olması engellenmeli.

Çözüm 1: Pessimistic Locking (Kilitleyici Yöntem)

@Transactional public boolean withdraw(Long accountId, BigDecimal amount) { // SELECT ... FOR UPDATE - veritabanı satırı kilitler Account account = accountRepo.findByIdWithLock(accountId); if (account.getBalance().compareTo(amount) >= 0) { account.setBalance(account.getBalance().subtract(amount)); accountRepo.save(account); return true; } return false; }

Çözüm 2: Optimistic Locking (Versiyon Kontrolü)

@Entity public class Account { @Id Long id; BigDecimal balance; @Version Long version; // Her güncelleme artırılır } @Transactional public void withdraw(Long accountId, BigDecimal amount) { Account account = accountRepo.findById(accountId).get(); if (account.getBalance().compareTo(amount) >= 0) { account.setBalance(account.getBalance().subtract(amount)); // Eğer version değişmişse: OptimisticLockingFailureException accountRepo.save(account); } } // Çağrıcı tarafında retry: int retry = 3; while (retry > 0) { try { withdraw(accountId, amount); break; } catch (OptimisticLockingFailureException e) { retry--; if (retry == 0) throw e; Thread.sleep(100); // Geri kalan retry'lar için bekleme } }

Çözüm 3: Atomik SQL Güncelleme (En İyi)

@Transactional public void withdraw(Long accountId, BigDecimal amount) { int updated = accountRepo.decrementBalanceIfSufficient(accountId, amount); if (updated == 0) { throw new InsufficientFundsException(); } } // Repository @Query(""" UPDATE Account a SET a.balance = a.balance - :amount WHERE a.id = :id AND a.balance >= :amount """) @Modifying int decrementBalanceIfSufficient( @Param("id") Long id, @Param("amount") BigDecimal amount );

Ek Güvenlik Mekanizmaları:

Idempotency Anahtarı:

  • Her işlem için UUID oluştur (client tarafından)
  • Veritabanına depo et
  • Aynı UUID ile tekrar gelirse önceki sonucu dön
@Table(uniqueConstraints = @UniqueConstraint(columnNames = "idempotencyKey")) public class Transaction { @Id Long id; String idempotencyKey; // Unique! BigDecimal amount; Status status; } // İlk istek transactionRepo.findByIdempotencyKey("abc-123-def"); // Bulunamadı, işlem yap // Tekrar istek (same idempotencyKey) transactionRepo.findByIdempotencyKey("abc-123-def"); // Bulundu, sonucu dön
Çoklu instance ortamında: pessimistic locking veritabanı seviyesinde çalışır, bu da güvendir. Optimistic locking retry gerektir fakat throughput daha yüksektir.

Soru 12:
Aspect-Oriented Programming (AOP) Nedir?

AOP Nedir?

Cross-cutting concerns'leri (logging, security, transaction) ana business logic'ten ayırmaya yarayan teknik.

AOP Temel Terimleri:

AOP Sözlüğü:

  • Aspect: AOP modülü (class)
  • Join Point: Advice uygulanabilen kod noktası (method call, exception)
  • Pointcut: Join point'leri seçen expression (@Pointcut)
  • Advice: Pointcut'a yapılacak işlem (Before, After, Around)

Pratik Örnek: Logging Aspect

@Aspect @Component public class LoggingAspect { @Pointcut("execution(* com.example.service.*.*(..))") public void serviceLayer() {} @Before("serviceLayer()") public void logBefore(JoinPoint joinPoint) { String methodName = joinPoint.getSignature().getName(); logger.info("Metod çağrıldı: " + methodName); } @After("serviceLayer()") public void logAfter(JoinPoint joinPoint) { logger.info("Metod tamamlandı: " + joinPoint.getSignature().getName()); } @Around("serviceLayer()") public Object logAround(ProceedingJoinPoint pjp) throws Throwable { long start = System.currentTimeMillis(); Object result = pjp.proceed(); // Asıl metod çalışır long duration = System.currentTimeMillis() - start; logger.info("Süre: " + duration + "ms"); return result; } }

Annotation-Based Pointcut Örneği:

// 1. Custom annotation tanımla @Target(ElementType.METHOD) @Retention(RetentionPolicy.RUNTIME) public @interface LogExecution { } // 2. Aspect'i yazıyor @Aspect @Component public class ExecutionLogAspect { @Around("@annotation(LogExecution)") public Object log(ProceedingJoinPoint pjp) throws Throwable { System.out.println("START: " + pjp.getSignature()); Object result = pjp.proceed(); System.out.println("END: " + pjp.getSignature()); return result; } } // 3. Service'te kullan @Service public class UserService { @LogExecution // Bu metod log'lanacak public void createUser(User user) { // business logic } }

Self-Invocation Problemi:

@Service public class PaymentService { @Transactional public void pay(Order order) { deductBalance(order.getAmount()); // Aspect çalışmaz! } @Transactional private void deductBalance(BigDecimal amount) { // ... } } // Sorun: pay() içinden deductBalance() çağrıldığında, // proxy'den geçmediği için Aspect uygulanmaz. // Çözüm 1: Inject ApplicationContext ve bean'i çağır // Çözüm 2: deductBalance'ı başka bir service'e taşı // Çözüm 3: public yap (iyi practice değildir)
Spring AOP proxy-based'dir, yani reflection kullanır. Buna rağmen hızlı ama tüm reflection sınırlamaları vardır (private metod, constructor vs.)
AspectJ kullanarak bytecode manipulation yapabilirsiniz (constructor, private metod vs. için), ancak setup daha karmaşıktır.
Soru 13:
Spring Circular Dependencies Nasıl Yönetir?

Circular Dependency Nedir?

A bean'i B bean'e, B bean'i ise A bean'e bağımlı olduğunda meydana gelir.

Durum 1: Constructor Injection - BAŞARISIZ

@Service public class ServiceA { private ServiceB serviceB; // Constructor injection public ServiceA(ServiceB serviceB) { // ❌ Circular! this.serviceB = serviceB; } } @Service public class ServiceB { private ServiceA serviceA; public ServiceB(ServiceA serviceA) { // ❌ Circular! this.serviceA = serviceA; } } // Başlarken: UnsatisfiedDependencyException!

Durum 2: Setter/Field Injection - BAŞARILI (Dikkatli)

@Service public class ServiceA { @Autowired // ✓ Setter/field injection private ServiceB serviceB; } @Service public class ServiceB { @Autowired // ✓ Setter/field injection private ServiceA serviceA; } // Spring bunu çözer (early bean reference'lar sayesinde) // Ancak service'ler başlangıçta null olabilir!

Çözüm 1: Architecture Tasarımını Değiştir

// Sorunlu tasarım: // ServiceA -> ServiceB -> ServiceA // Çözüm: Yeni service ekle @Service public class ServiceC { @Autowired private ServiceA serviceA; @Autowired private ServiceB serviceB; public void doSomething() { serviceA.doA(); serviceB.doB(); } }

Çözüm 2: Events Kullan (Decoupled)

// Event tanımı public class OrderCreatedEvent { private Order order; // getter/setter } // ServiceA - event yayınlayan @Service public class ServiceA { @Autowired private ApplicationEventPublisher eventPublisher; public void createOrder(Order order) { eventPublisher.publishEvent(new OrderCreatedEvent(order)); } } // ServiceB - event dinleyen (bağımlı değil!) @Service public class ServiceB { @EventListener public void handleOrderCreated(OrderCreatedEvent event) { // Order işleme } } // Hiç circular dependency yok!

Çözüm 3: Lazy Initialization

@Service public class ServiceA { @Autowired @Lazy private ServiceB serviceB; // İhtiyaç duyulduğunda başlatılır }
En iyi uygulama: Circular dependency'i tasarımdan çıkarmaktır. Event-driven yaklaşımı kullanın.
Soru 14:
JWT ve OAuth 2.0 ile REST API'ları Nasıl Secure Yaparım?

Authentication vs Authorization

Authentication: "Siz kimsiniz?" (giriş yapan kişi)

Authorization: "Ne yapabilirsiniz?" (izin kontrolü)

JWT (JSON Web Token) Nedir?

İmzalı bir token, kendi içinde kullanıcı bilgisi taşır. Server-side session gerektirmez.

// JWT yapısı: Header.Payload.Signature // eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhbGkiLCJpYXQiOjE2MzQ3NTY4MDB9.xxx // Header: {"alg":"HS256"} // Payload: {"sub":"ali","iat":1634756800,"exp":1634760400} // Signature: HMAC-SHA256(Header.Payload, secret_key)

OAuth 2.0 Authorization Code Flow

1. User: Uygulamaya giriş için OAuth provider'a yönlendir 2. Provider: User login yap, permission sor 3. Provider: Authorization code gönder 4. App Backend: Authorization code + client_secret ile token iste 5. Provider: Access token ve refresh token gönder 6. App Backend: Access token ile API çağrılarını yap

return true; } catch (JwtException | IllegalArgumentException e) { return false; } } } // Filter @Component public class JwtAuthenticationFilter extends OncePerRequestFilter { @Autowired private JwtTokenProvider tokenProvider; @Override protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) throws ServletException, IOException { try { String jwt = getJwtFromRequest(request); if (jwt != null && tokenProvider.validateToken(jwt)) { String username = tokenProvider.getUsernameFromToken(jwt); UserDetails userDetails = loadUserDetails(username); Authentication auth = new UsernamePasswordAuthenticationToken( userDetails, null, userDetails.getAuthorities()); SecurityContextHolder.getContext().setAuthentication(auth); } } catch (Exception e) { logger.error("JWT filter error", e); } filterChain.doFilter(request, response); } private String getJwtFromRequest(HttpServletRequest request) { String bearerToken = request.getHeader("Authorization"); if (bearerToken != null && bearerToken.startsWith("Bearer ")) { return bearerToken.substring(7); } return null; } } // Login Controller @RestController @RequestMapping("/api/auth") public class AuthController { @Autowired private JwtTokenProvider tokenProvider; @PostMapping("/login") public ResponseEntity login(@RequestBody LoginRequest request) { // Username/password doğrula (authenticate) // İlgili user'ı yükle String token = tokenProvider.generateToken(request.getUsername()); return ResponseEntity.ok(new JwtAuthenticationResponse(token)); } } // Protected endpoint @RestController @RequestMapping("/api/users") public class UserController { @GetMapping("/me") @PreAuthorize("isAuthenticated()") // JWT valid olmalı public ResponseEntity getCurrentUser() { String username = SecurityContextHolder.getContext() .getAuthentication().getName(); return ResponseEntity.ok(userService.findByUsername(username)); } }

Refresh Token Pattern

// Access token kısa (15 min), refresh token uzun (7 days) @PostMapping("/refresh") public ResponseEntity refreshToken(@RequestBody RefreshTokenRequest request) { if (!tokenProvider.validateRefreshToken(request.getRefreshToken())) { return ResponseEntity.status(401).build(); } String username = tokenProvider.getUsernameFromToken(request.getRefreshToken()); String newAccessToken = tokenProvider.generateToken(username); return ResponseEntity.ok(new JwtAuthenticationResponse(newAccessToken)); }

JWT'i bir kez verify etmek yeterlidir, sonraki isteklerde cache'de tutabilirsiniz. Token revocation gerektiyorsa blacklist maintain etmeniz gerekir.

Soru 15:
Spring Boot Auto-Configuration Nasıl Çalışır?

Auto-Configuration Nedir?

Spring Boot, classpath'te gördüğü kütüphanelere göre otomatik bean'ler oluşturur. Örneğin, DataSource jar'ı varsa, otomatik DataSource bean'i yaratılır.

Nasıl Çalışır?

1. @SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan 2. @EnableAutoConfiguration spring.factories dosyasından auto-config class'larını yükler 3. Conditional annotations kontrol edilir: - @ConditionalOnClass - Bu class classpath'te mi? - @ConditionalOnMissingBean - Bu bean'i user yaratmadı mı? - @ConditionalOnProperty - Bu property enabled mi? 4. Koşullar sağlanırsa bean oluşturulur

spring.factories Nedir?

# spring-boot-autoconfigure.jar içinde META-INF/spring.factories org.springframework.boot.autoconfigure.EnableAutoConfiguration=\ org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration,\ org.springframework.boot.autoconfigure.orm.jpa.HibernateJpaAutoConfiguration,\ org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration,\ ...

Örnek: DataSourceAutoConfiguration

@Configuration @ConditionalOnClass(DataSource.class) // org.springframework.jdbc.datasource.DataSource jar'ında mı? @ConditionalOnMissingBean(DataSource.class) // User bean yaratmadı mı? @EnableConfigurationProperties(DataSourceProperties.class) public class DataSourceAutoConfiguration { @Bean public DataSource dataSource(DataSourceProperties properties) { // application.yml'den oku return properties.initializeDataSourceBuilder().build(); } }

application.yml'de Konfigürasyon:

spring: datasource: url: jdbc:mysql://localhost:3306/mydb username: root password: secret driver-class-name: com.mysql.cj.jdbc.Driver jpa: hibernate: ddl-auto: update

Auto-Config Disable Etme:

// Tek bir auto-config'i disable et @SpringBootApplication(exclude = DataSourceAutoConfiguration.class) public class MyApp { } // Veya application.yml'de: spring: autoconfigure: exclude: - org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration

Custom Auto-Configuration Yazma:

// CustomAutoConfiguration.java @Configuration @ConditionalOnClass(MyService.class) @ConditionalOnMissingBean(MyService.class) public class MyServiceAutoConfiguration { @Bean @ConditionalOnProperty(name = "myapp.service.enabled", havingValue = "true") public MyService myService() { return new MyService(); } } // resources/META-INF/spring.factories org.springframework.boot.autoconfigure.EnableAutoConfiguration=\ com.example.MyServiceAutoConfiguration

Auto-Configuration Neden Çalışmadığını Debug Etme:

// 1. Hangi auto-configs'ler uygulandığını görmek java -Ddebug -jar myapp.jar // 2. application.yml'de logging: level: org.springframework.boot.autoconfigure: DEBUG // 3. /actuator/conditions endpoint'ine bakın (Spring Boot Actuator gerekli)
Spring Boot 2.7+: spring.factories yerine spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports kullanılıyor.

application.properties vs application.yml - Hangisini Kullanmalı?
Özellik application.properties application.yml
Format key=value Hierarchical YAML
Readability Basit ama verbose Temiz ve hiyerarşik
Performance Hafif daha hızlı Minimal fark

application.properties Örneği:

spring.datasource.url=jdbc:mysql://localhost:3306/mydb spring.datasource.username=root spring.datasource.password=secret spring.jpa.hibernate.ddl-auto=update server.port=8080 logging.level.root=INFO

application.yml Örneği (Tercih Edilen):

spring: datasource: url: jdbc:mysql://localhost:3306/mydb username: root password: secret jpa: hibernate: ddl-auto: update server: port: 8080 logging: level: root: INFO

Profile-Specific Configuration:

application.yml (default) application-dev.yml (development) application-prod.yml (production) application-test.yml (testing) // Çalıştırma: java -Dspring.profiles.active=prod -jar app.jar // veya ENV: SPRING_PROFILES_ACTIVE=prod

Secret Management - Passwords Hiçbir Zaman Commit Yapmayın:

# 1. Environment variables kullan export DB_PASSWORD=secret123 export API_KEY=abc-xyz-123 # 2. application.yml spring: datasource: password: ${DB_PASSWORD} # 3. Veya .env file (spring-dotenv) # 4. Production: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault
Passwords, API keys, credentials'ları source control'e push etmeyin! GitHub'a .git push yapmadan önce secrets scan edin.
YAML kullanmanızı önerim: daha readable, hiyerarşik yapı, nested properties'ler daha temiz.
Soru 17:
ApplicationContext vs BeanFactory - Arasındaki Fark?
Özellik BeanFactory ApplicationContext
Scope Core interface BeanFactory'i extend eder
Bean Management ✓ Temel ✓ Geliştirilmiş
Events ✗ ✓ ApplicationEvent support
I18n (Internationalization) ✗ ✓
Resource Loading ✗ ✓ ResourceLoader
Initialization Manual (lazy) Automatic (eager)

BeanFactory - Minimal Konfigürasyon:

// Spring XML config'ine ihtiyacınız var BeanFactory factory = new XmlBeanFactory( new ClassPathResource("applicationContext.xml")); // Bean'i al UserService service = factory.getBean("userService", UserService.class); // Lazy: Bean'ler ancak getBean çağrıldığında yaratılır

ApplicationContext - Tam Özellik:

// Java config ApplicationContext context = new AnnotationConfigApplicationContext(AppConfig.class); // veya XML config ApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml"); // veya Spring Boot (otomatik) @SpringBootApplication public class MyApp { public static void main(String[] args) { ApplicationContext context = SpringApplication.run(MyApp.class, args); UserService service = context.getBean(UserService.class); } } // Eager: Uygulama başladığında tüm singleton'lar yaratılır // Events: ApplicationEventPublisher var // I18n: MessageSource var // Resource: ResourceLoader var

Pratik Fark:

// BeanFactory - Yavaş başlama (lazy loading) // ApplicationContext - Biraz daha yavaş (eager loading ama tüm bean'ler hazır) // Spring Boot'ta ApplicationContext kullanılır (arka planda) // Genellikle ApplicationContext size verir (tümünü)
Günümüzde BeanFactory nadiren direkt kullanılır. Spring Boot ve ApplicationContext standart haline geldi. BeanFactory, IoC container'ın minimal interface'idir.
Soru 18:
Order Sisteminde Inventory, Payment ve Invoice Services Nasıl Decouple Edilir?

Problem Senaryosu:

Order alındı → Inventory decrement et → Payment işle → Invoice oluştur

Eğer Payment başarısız olursa inventory'i geri almamız lazım (saga pattern).

Çözüm 1: Spring ApplicationEvents (Single Application)

// Event tanımı public class OrderCreatedEvent extends ApplicationEvent { private Order order; public OrderCreatedEvent(Object source, Order order) { super(source); this.order = order; } public Order getOrder() { return order; } } // Order Service - Event yayınlar @Service public class OrderService { @Autowired private ApplicationEventPublisher eventPublisher; @Transactional public Order createOrder(Order order) { // Order'ı DB'ye kaydet Order savedOrder = orderRepository.save(order); // Diğer service'lere haber ver (asynchronous!) eventPublisher.publishEvent(new OrderCreatedEvent(this, savedOrder)); return savedOrder; } } // Inventory Service - Event dinler @Service public class InventoryService { @EventListener @Async @Transactional public void handleOrderCreated(OrderCreatedEvent event) { Order order = event.getOrder(); boolean reserved = inventoryRepository.reserveItems(order.getId(), order.getItems()); if (!reserved) { // Başarısız: event yayınla eventPublisher.publishEvent(new InventoryReservationFailedEvent(...)); } } } // Payment Service - Event dinler @Service public class PaymentService { @EventListener @Async @Transactional public void handleOrderCreated(OrderCreatedEvent event) { Order order = event.getOrder(); boolean paid = processPayment(order); if (paid) { eventPublisher.publishEvent(new PaymentCompletedEvent(...)); } else { eventPublisher.publishEvent(new PaymentFailedEvent(...)); } } @EventListener @Async public void handlePaymentFailed(PaymentFailedEvent event) { // Inventory'i geri al inventoryService.cancelReservation(event.getOrderId()); } } // Invoice Service - Event dinler @Service public class InvoiceService { @EventListener @Async @Transactional public void handlePaymentCompleted(PaymentCompletedEvent event) { Invoice invoice = invoiceRepository.create(event.getOrderId()); emailService.sendInvoice(invoice); } } // Config: @Async support @Configuration @EnableAsync public class AsyncConfig { @Bean public Executor taskExecutor() { ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor(); executor.setCorePoolSize(2); executor.setMaxPoolSize(5); executor.initialize(); return executor; } }

Çözüm 2: Messaging (Kafka/RabbitMQ) - Distributed Systems

// Order Service @Service public class OrderService { @Autowired private KafkaTemplate<String, OrderEvent> kafkaTemplate; @Transactional public Order createOrder(Order order) { Order saved = orderRepository.save(order); // Kafka'ya mesaj gönder kafkaTemplate.send("order-events", new OrderCreatedEvent(saved)); return saved; } } // Inventory Service (ayrı instance) @Service public class InventoryService { @KafkaListener(topics = "order-events") public void handleOrderCreated(OrderCreatedEvent event) { boolean reserved = inventoryRepository.reserveItems(...); if (!reserved) { // Failure event yayınla kafkaTemplate.send("inventory-events", new InventoryFailedEvent(...)); } } } // Payment Service (ayrı instance) @Service public class PaymentService { @KafkaListener(topics = "order-events") public void handleOrderCreated(OrderCreatedEvent event) { boolean paid = processPayment(event.getOrder()); if (paid) { kafkaTemplate.send("payment-events", new PaymentCompletedEvent(...)); } } @KafkaListener(topics = "inventory-events") public void handleInventoryFailed(InventoryFailedEvent event) { // Compensation: Order cancel kafkaTemplate.send("order-events", new OrderCancelledEvent(...)); } }

Çözüm 3: Saga Pattern (Distributed Transaction)

// Choreography (event-driven) vs Orchestration (service-driven) // Orchestration örneği: @Service public class OrderOrchestrator { @Autowired private InventoryService inventoryService; @Autowired private PaymentService paymentService; @Autowired private InvoiceService invoiceService; @Transactional public Order executeOrderSaga(Order order) { Order savedOrder = orderRepository.save(order); try { // Adım 1 inventoryService.reserve(savedOrder); // Adım 2 paymentService.pay(savedOrder); // Adım 3 invoiceService.create(savedOrder); return savedOrder; } catch (Exception e) { // Rollback tüm işlemleri inventoryService.cancel(savedOrder); paymentService.refund(savedOrder); throw new OrderProcessingException(e); } } }

Idempotency Anahtar Kullanımı:

// Payment isteği duplicate olabilir // Aynı idempotency key'le çağrıldığında aynı sonuç dön @Service public class PaymentService { @Transactional public PaymentResult pay(Order order, String idempotencyKey) { // Eğer bu key'le daha önceki istek varsa sonucu dön PaymentResult existing = paymentRepository.findByIdempotencyKey(idempotencyKey); if (existing != null) { return existing; } // Yeni ödeme işle PaymentResult result = processActualPayment(order); result.setIdempotencyKey(idempotencyKey); return paymentRepository.save(result); } }

Seçim Kriterleri:

  • Single Application: Events
  • Few Services: Choreography (Kafka events)
  • Complex Flow: Orchestration (Saga pattern)
  • Strict Consistency: Database transactions
  • Eventual Consistency: Messaging + Compensation
Distributed transaction'larda eventual consistency'i kabul etmelisiniz. ACID garantisi zor olmaktadır, bunun yerine BASE (Basically Available, Soft state, Eventual consistency) modelini kullanın.

Soru 19:
Hibernate get() vs load() - Fark Nedir?
Özellik get() load()
DB Query Hemen yapılır Lazy (lazy proxy)
Entity Bulunamadı null dönür LazyInitializationException
Cache Kontrolü ✓ First-level cache kontrol ✓ First-level cache kontrol
Dönüş Tipi Gerçek Entity Proxy obje
// get() - Eager loading User user = session.get(User.class, 1); // SELECT * FROM users WHERE id = 1 (hemen çalışır) if (user == null) { System.out.println("User bulunamadı"); } else { System.out.println(user.getName()); } // load() - Lazy loading (Deprecated/Removed Hibernate 6+) User user = session.load(User.class, 1); // Hiç query çalışmaz! System.out.println(user.getName()); // Burada query çalışır // Eğer user yoksa LazyInitializationException!

Modern Alternatif (Hibernate 6+):

// getReference() - load() yerine kullanılır (EntityManager) User user = entityManager.getReference(User.class, 1); // Lazy proxy, query yok System.out.println(user.getName()); // Query çalışır // JpaRepository User user = repository.getById(1); // Reference (lazy)
load() ve getReference() exception fırlatabilir, eger lazy loading session kapalı olduğunda. get()/find() daha güvenlidir.
